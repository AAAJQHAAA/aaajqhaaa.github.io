# WebRTC 基础与协议栈

## 一、WebRTC 是什么

WebRTC (Web Real-Time Communication) 使网页应用能够：
- **捕获音视频**（摄像头、麦克风）
- **点对点传输**任意数据
- **视频通话**无需中间服务器

### 核心能力

| 能力 | 说明 |
|------|------|
| 音视频通话 | 实时传输音频/视频 |
| 屏幕共享 | 共享屏幕内容 |
| 数据通道 | 传输任意二进制数据（没啥用） |
| 电话集成 | 支持 DTMF（拨号音）（没啥用） |

```
浏览器 A ←─── WebRTC ───→ 浏览器 B
```

## 四、协议关系

### 1. SDP（会话描述协议）——"我是谁，我要什么"

**通俗理解**：双方交换的"名片"，写清楚自己支持什么音视频格式、想要什么。

```
发送方：我有音频(G.711)、视频(H.264)，想和你通话
接收方：我支持音频(Opus)、视频(VP8)，可以！
```

### 2. ICE（交互式连接建立）——"怎么找到对方"

**通俗理解**：找路策略，依次尝试：
1. **直连 UDP** → 最快（局域网或公网直接打洞成功）
2. **直连 TCP** → 次快
3. **TURN 中继** → 最慢但最可靠（打洞失败时的兜底）

### 3. STUN/TURN（NAT 穿透技术）——"如何穿越防火墙"

- 问题：路由器给每台设备分配**私有 IP**，对外只有一个**公网 IP**。

| 协议 | 作用 | 速度 |
|------|------|------|
| **STUN** | 帮你找到自己的公网 IP:端口 | 快 |
| **TURN** | 帮你们中继数据（当直连失败时） | 慢 |

**通俗理解**：
- STUN = 问你爸你家门牌号是几号
- TURN = 你爸不在家时，找邻居家转交

### 4. DTLS（加密）—— "说的话要加密"

WebRTC 所有传输数据**必须加密**，DTLS 为数据报提供加密（类似 TLS 的 UDP 版本）。

### 5. RTP/RTCP（音视频传输）—— "怎么传音视频"

| 协议 | 作用 |
|------|------|
| **RTP** | 传输音视频数据（实时） |
| **RTCP** | 传输控制信息（质量反馈、统计） |

**通俗理解**：RTP = 快递包裹，RTCP = 快递追踪系统

### 6. SCTP（数据通道）—— "怎么传数据"

用于 WebRTC 的 **DataChannel**，可靠传输消息（类似 TCP）。

### 7. Jitter（抖动）—— "到达时间不一致"

**问题**：数据包到达忽快忽慢
**解决**：抖动缓冲区，稳输出

## 五、建立通话简化流程

```
1. 打开摄像头/麦克风 → getUserMedia()
                    ↓
2. 交换 SDP（能力协商：我支持什么格式）
                    ↓
3. ICE 协商（找路：直连 or STUN or TURN）
                    ↓
4. DTLS 加密（建立安全通道）
                    ↓
5. RTP/SRTP 传输音视频
                    ↓
6. RTCP 质量监控（丢包、延迟反馈）
```

## 六、快速记忆

| 协议 | 核心问题 | 一句话 |
|------|---------|--------|
| SDP | 说什么？ | 描述会话能力 |
| ICE | 怎么连？ | 选择最佳连接路径 |
| STUN | 我在哪？ | 发现公网地址 |
| TURN | 连不上怎么办？ | 中继转发 |
| DTLS | 安全吗？ | 数据加密 |
| RTP | 怎么传？ | 实时传输音视频 |
| RTCP | 传得好吗？ | 质量监控 |
| SCTP | 数据怎么传？ | DataChannel 协议 |
