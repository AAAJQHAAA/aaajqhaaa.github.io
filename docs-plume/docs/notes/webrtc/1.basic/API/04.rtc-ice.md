# WebRTC ICE 协商完全指南

> ICE 候选、候选配对、参数与事件

---

## 概述

ICE（Interactive Connectivity Establishment）是 WebRTC 建立连接的协议，负责找到两个设备之间的最佳通信路径。

**核心接口**：

| 接口 | 职责 |
|------|------|
| `RTCIceCandidate` | 单个候选者（网络路径） |
| `RTCIceCandidatePair` | 候选配对（本地+远程） |
| `RTCIceParameters` | ICE 认证参数 |
| `RTCPeerConnectionIceEvent` | 候选事件 |
| `RTCPeerConnectionIceErrorEvent` | ICE 错误事件 |
| `RTCIceCandidatePairStats` | 配对统计（连接质量） |
| `RTCIceCandidateStats` | 候选统计 |

**ICE 流程**：

```
┌─────────────┐         ┌─────────────┐
│   本地端     │         │   远端       │
└──────┬──────┘         └──────┬──────┘
       │                       │
       │──── ICE Candidates ──→│
       │←─── ICE Candidates ──│
       │                       │
       │     找到最佳路径        │
       │     开始通信            │
```

## 候选类型

```
候选类型优先级（高 → 低）：

┌─────────────────────────────────────────────────┐
│  host      → 本地网络IP（同一局域网）           │
│  srflx     → 公网IP（通过STUN发现）             │
│  prflx     → 对等反射（NAT打洞直接获取）        │
│  relay     → TURN中继（最稳定，但有延迟）       │
└─────────────────────────────────────────────────┘
```

| type | 全拼 | 怎么来 | 能否穿透 NAT |
|---|---|---|---|
| **host** | host candidate | 本机网卡直接绑的 IP + 端口 | 同局域网直连 OK；跨公网几乎不行（家庭路由器是锥形 NAT 的受害者） |
| **srflx** | server reflexive | 向 STUN 发 Binding Request，STUN 服务看到你「外面的出口 IP + port」后返回 | 能穿透大多数 Full Cone / Restricted Cone NAT；对称 NAT 不行 |
| **prflx** | peer reflexive | 对端发 STUN 过来的源地址/端口跟 STUN 上报的不一致，ICE 连通性检查过程自动发现 | 几乎总是临时产物，最终稳定成 srflx/relay |
| **relay** | relayed candidate | 向 TURN 服务器发 Allocate 申请到的「中继地址」 | **任何情况都能通**（代价 = 走 TURN 服务器带宽，最贵） |

## RTCIceCandidate

> ICE 候选者接口

### 构造函数

```js
new RTCIceCandidate()
new RTCIceCandidate(candidateInfo)
```

**candidateInfo 参数**（可选）：

| 属性 | 类型 | 说明 |
|------|------|------|
| `candidate` | string | 候选者字符串（SDP 属性） |
| `sdpMid` | string | 媒体流标识 |
| `sdpMLineIndex` | number | m-line 索引 |
| `usernameFragment` | string | 用户名片段（ice-ufrag） |

### 属性

#### candidate — 候选者字符串

完整候选者信息。

```js
candidate.candidate  // string
```

**格式**：`candidate:<foundation> <component> <protocol> <priority> <ip> <port> typ <type> ...`

**示例**：
```
a=candidate:4234997325 1 udp 2043278322 192.0.2.172 44323 typ host
```

> 空字符串 `""` 表示"候选者结束"标记。

#### type — 候选者类型

```js
candidate.type  // "host" | "srflx" | "prflx" | "relay"
```

#### address — IP 地址

```js
candidate.address  // string | null
```

#### port — 端口号

```js
candidate.port  // number | null
```

#### protocol — 传输协议

```js
candidate.protocol  // "udp" | "tcp"
```

#### tcpType — TCP 类型

当 `protocol` 为 `"tcp"` 时：

```js
candidate.tcpType  // "active" | "passive" | "so" | null
```

| 值 | 说明 |
|----|------|
| `active` | 尝试打开出站连接 |
| `passive` | 接收入站请求 |
| `so` | 同时打开连接 |

#### component — 组件类型

```js
candidate.component  // "rtp" | "rtcp"
```

#### priority — 优先级

```js
candidate.priority  // number | null
```

#### foundation — 标识符

相同 foundation 的候选者：类型相同、来自同一 IP/STUN/TURN 服务器。

```js
candidate.foundation  // string
```

#### relatedAddress / relatedPort

对于中继或反射候选者，表示派生自的主机候选者。

```js
candidate.relatedAddress  // string | null
candidate.relatedPort    // number | null
```

#### sdpMid / sdpMLineIndex

媒体流标识和 m-line 索引。

```js
candidate.sdpMid       // string | null
candidate.sdpMLineIndex // number | null
```

## RTCIceCandidatePair

> 候选配对接口

### 概述

`RTCIceCandidatePair` 描述一对 ICE 候选者（本地+远程），代表完整可行连接。

### 属性

```js
candidatePair.local   // RTCIceCandidate（本地）
candidatePair.remote  // RTCIceCandidate（远程）
```

### 候选配对示意

```
┌─────────────────────────────────────────────────┐
│              RTCIceCandidatePair                │
├─────────────────────────────────────────────────┤
│  local  ────→  RTCIceCandidate (本地)          │
│           │     - address: "192.168.1.100"     │
│           │     - port: 54321                  │
│           │     - type: "host"                 │
│                                                  │
│  remote ────→  RTCIceCandidate (远程)          │
│               - address: "203.0.113.50"        │
│               - port: 54321                    │
│               - type: "prflx"                  │
└─────────────────────────────────────────────────┘
```

### 使用示例

```js
const candidatePair = pc
  .getSenders()[0]
  .transport.iceTransport.getSelectedCandidatePair();

console.log('本地:', candidatePair.local.address);
console.log('远程:', candidatePair.remote.address);
```

## RTCIceParameters

> ICE 会话参数

### 概述

指定 ICE 会话的用户名片段和密码，用于认证。

### 属性

```js
params.usernameFragment  // string
params.password          // string
```

### 安全机制

```
usernameFragment + password
       │
       ├── 唯一标识 ICE 会话
       ├── 防止跨会话干扰（crosstalk）
       └── 用于消息完整性验证
```

### 使用示例

```js
const iceTransport = pc.getSenders()[0].transport.iceTransport;
const localParams = iceTransport.getLocalParameters();

console.log('用户名片段:', localParams.usernameFragment);
console.log('密码:', localParams.password);
```

## ICE 事件

### RTCPeerConnectionIceEvent

> ICE 候选事件

**触发时机**：`icecandidate` 事件在收到或创建新候选时触发。

```js
pc.onicecandidate = (event) => {
  if (event.candidate) {
    // 发送候选者给对等端
    signalingChannel.send({
      type: 'candidate',
      candidate: event.candidate
    });
  } else {
    // 没有更多候选者
    console.log('ICE 候选者收集完成');
  }
};
```

**属性**：

| 属性 | 说明 |
|------|------|
| `candidate` | ICE 候选者对象或 `null` |
| `url` | STUN/TURN 服务器 URL（已废弃） |

### RTCPeerConnectionIceErrorEvent

> ICE 错误事件

**触发时机**：`icecandidateerror` 事件在 STUN/TURN 请求失败时触发。

```js
pc.onicecandidateerror = (event) => {
  console.error('ICE 错误码:', event.errorCode);
  console.error('错误描述:', event.errorText);
  console.error('服务器 URL:', event.url);
  console.error('本地地址:', event.address);
};
```

**属性**：

| 属性 | 说明 |
|------|------|
| `address` | 本地 IP 地址 |
| `errorCode` | STUN 错误码 |
| `errorText` | 错误描述 |
| `port` | 端口号 |
| `url` | 服务器 URL |

**常见错误码**：

| 错误码 | 说明 |
|--------|------|
| 400 | 请求格式错误 |
| 401 | 未授权 |
| 403 | 禁止访问 |
| 420 | 未知属性 |
| 430 | STUN 版本不兼容 |
| 500 | 服务器内部错误 |
| 600 | 全球约束失败 |
| 701 | 无法到达服务器 |

## ICE 统计

### RTCIceCandidatePairStats

> 候选配对统计

**获取方式**：`RTCPeerConnection.getStats()` 中 `type` 为 `"candidate-pair"` 的条目。

#### 状态机

```
┌─────────┐     检查开始      ┌─────────────┐
│ frozen  │ ──────────────→  │   waiting   │
└─────────┘                  └─────────────┘
                                  │
                            检查触发  │
                                  ↓
                          ┌─────────────┐
                          │ in-progress │
                          └─────────────┘
                              │       │
                         成功 │       │ 失败
                              ↓       ↓
                      ┌───────────┐ ┌────────┐
                      │ succeeded │ │ failed │
                      └───────────┘ └────────┘
```

#### 属性分类

**候选标识**：

| 属性 | 说明 |
|------|------|
| `localCandidateId` | 本地候选者 ID |
| `remoteCandidateId` | 远程候选者 ID |

**连接状态**：

| 属性 | 说明 |
|------|------|
| `state` | 候选配对状态 |
| `nominated` | 是否已被提名 |

**字节/数据包统计**：

| 属性 | 说明 |
|------|------|
| `bytesReceived` | 接收字节数 |
| `bytesSent` | 发送字节数 |
| `packetsReceived` | 接收数据包数 |
| `packetsSent` | 发送数据包数 |

**往返时间**：

| 属性 | 说明 |
|------|------|
| `currentRoundTripTime` | 当前 RTT（秒） |
| `totalRoundTripTime` | 总 RTT（秒） |

**带宽**：

| 属性 | 说明 |
|------|------|
| `availableIncomingBitrate` | 可用入站带宽（bps） |
| `availableOutgoingBitrate` | 可用出站带宽（bps） |

#### 使用示例

```js
const stats = await myPeerConnection.getStats();

stats.forEach((report) => {
  if (report.type === "candidate-pair") {
    console.log('配对状态:', report.state);
    console.log('当前 RTT:', report.currentRoundTripTime, '秒');
    console.log('可用入站带宽:', report.availableIncomingBitrate, 'bps');
  }
});
```

### RTCIceCandidateStats

> 候选者统计

**获取方式**：`RTCPeerConnection.getStats()` 中 `type` 为 `"local-candidate"` 的条目。

#### 属性

| 属性 | 说明 |
|------|------|
| `address` | IP 地址或域名 |
| `port` | 端口号 |
| `protocol` | 传输协议（udp/tcp） |
| `candidateType` | 候选者类型 |
| `foundation` | 关联标识符 |
| `priority` | 优先级 |
| `usernameFragment` | 用户名片段 |
| `url` | ICE 服务器 URL |
| `relayProtocol` | TURN 协议 |
| `deleted` | 是否已删除 |

#### 筛选示例

```js
const hostCandidates = [];

stats.forEach((report) => {
  if (report.type === "local-candidate" && report.candidateType === "host") {
    hostCandidates.push(report);
  }
});
```

## 完整示例：ICE 协商

```js
const pc = new RTCPeerConnection({
  iceServers: [{ urls: 'stun:stun.l.google.com:19302' }]
});

// 1. 监听 ICE 候选
pc.onicecandidate = (event) => {
  if (event.candidate) {
    // 发送候选给对等端
    signalingChannel.send({
      type: 'candidate',
      candidate: event.candidate
    });
  }
};

// 2. 监听 ICE 错误
pc.onicecandidateerror = (event) => {
  console.error('ICE 错误:', event.errorCode, event.errorText);
};

// 3. 获取当前候选配对
setInterval(() => {
  const candidatePair = pc.getSenders()[0]?.transport?.iceTransport?.getSelectedCandidatePair();
  if (candidatePair) {
    console.log('连接路径:', candidatePair.local.address, '→', candidatePair.remote.address);
  }
}, 5000);

// 4. 处理收到的候选
async function handleCandidate(candidate) {
  try {
    await pc.addIceCandidate(candidate);
  } catch (err) {
    console.error('添加候选失败:', err);
  }
}
```
