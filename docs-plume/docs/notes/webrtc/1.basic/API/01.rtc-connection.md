# WebRTC 连接核心完全指南

> RTCPeerConnection、RTCDtlsTransport、RTCIceTransport、RTCSctpTransport

---

## 概述

连接核心模块包含 WebRTC 连接的核心接口：

| 接口 | 职责 |
|------|------|
| `RTCPeerConnection` | WebRTC 核心，管理层连接 |
| `RTCDtlsTransport` | DTLS 加密传输层 |
| `RTCIceTransport` | ICE 传输层 |
| `RTCSctpTransport` | SCTP 数据通道传输 |

**协议栈关系**：

```
┌─────────────────────────────────────────┐
│           RTCPeerConnection              │
│         (连接管理核心)                   │
├─────────────────────────────────────────┤
│              RTCDataChannel              │
│            (SCTP 应用层)                │
├─────────────────────────────────────────┤
│           RTCSctpTransport              │
│            (SCTP 传输层)                │
├─────────────────────────────────────────┤
│           RTCDtlsTransport              │
│          (DTLS 加密层)                  │
├─────────────────────────────────────────┤
│           RTCIceTransport               │
│          (ICE 传输层)                   │
└─────────────────────────────────────────┘
```

## RTCPeerConnection

> WebRTC 核心接口

### 构造函数

```js
new RTCPeerConnection(configuration)
```

**配置选项**：

| 选项 | 类型 | 说明 |
|------|------|------|
| `iceServers` | array | STUN/TURN 服务器列表 |
| `iceTransportPolicy` | string | `all` / `relay` |
| `bundlePolicy` | string | `balanced` / `max-compat` / `max-bundle` |
| `certificates` | array | DTLS 证书 |
| `iceCandidatePoolSize` | number | ICE 候选池大小 |

### 连接架构

```
┌─────────────────┐      signaling       ┌─────────────────┐
│   本地 Peer A   │◄──────(SDP)────────►│   远程 Peer B   │
│                 │                      │                 │
│  ┌───────────┐  │   ICE candidates    │  ┌───────────┐  │
│  │ MediaTrack│◄─┼─────(DTLS/SRTP)────┼─►│ MediaTrack│  │
│  └───────────┘  │                      │  └───────────┘  │
│  ┌───────────┐  │                      │  ┌───────────┐  │
│  │ DataChannel│◄┴─────(SCTP)────────►│  │ DataChannel│  │
│  └───────────┘  │                      │  └───────────┘  │
└─────────────────┘                      └─────────────────┘
```

### 协商流程

```
1. createOffer()         → 生成 SDP Offer
2. setLocalDescription()  → 设置本地描述
3. [发送 Offer 到服务器]
4. setRemoteDescription() → 设置远程描述
5. createAnswer()        → 生成 SDP Answer
6. setLocalDescription()  → 设置本地 Answer
7. [发送 Answer 到服务器]
8. addIceCandidate()     → 交换 ICE 候选
9. 连接建立完成
```

### 6 个状态机

| 属性 | 返回类型 | 典型流转 | 含义 |
|---|---|---|---|
| `.signalingState` | `RTCSignalingState` | `stable → have-local-offer → have-remote-pranswer → stable` | 本地 + 远端 offer/answer 是否「配对对称」 |
| `.iceGatheringState` | `RTCIceGatheringState` | `new → gathering → complete` | ICE 候选有没有收齐（Trickle ICE 过程中意义不大） |
| `.iceConnectionState` | `RTCIceConnectionState` | `new → checking → connected / completed → disconnected → failed → closed` | 只看 ICE 层的连通性（出问题时最有用） |
| `.connectionState` | `RTCPeerConnectionState` | `new → connecting → connected → disconnected → failed → closed` | ICE + DTLS + SCTP 三层汇总；**最推荐给上层 UI 展示用的那个** |
| `.sctp` | `RTCSctpTransport \| null` | — | DataChannel 的承载层；没协商 DataChannel 前 = null |
| `.canTrickleIceCandidates` | `boolean \| null` | — | 对端是否支持「来一个候选发一个」不用等 end-of-candidates |

### 14 个核心方法表

| 方法 | 作用 | 最常被调用阶段 |
|---|---|---|
| `createOffer({offerToReceiveAudio, offerToReceiveVideo, iceRestart}?)` | 生成 SDP offer | 发起方 |
| `createAnswer()?` | 基于当前 remoteDescription 生成 answer | 应答方 |
| `setLocalDescription(sdp?)` | 设置本方 SDP，启动 ICE 收集 | O/A 双方 |
| `setRemoteDescription(sdp)` | 吃下对端 SDP，开始匹配候选 | O/A 双方 |
| `addIceCandidate(candidate?)` | 注入对端候选（或 `end-of-candidates` 用 `null`） | Trickle 过程 |
| `addTrack(track, ...streams) → RTCRtpSender` | 加一条出向媒体 | O/A 前或 `negotiationneeded` 后重协商 |
| `removeTrack(sender)` | 移除一条发送（`direction` 自动转成 recvonly，要再 O/A） | 中途关摄像头 |
| `addTransceiver(trackOrKind, {direction, sendEncodings, streams}?)` | 底层：创建 Transceiver（Simulcast 必用） | 同上 |
| `getSenders()` / `getReceivers()` / `getTransceivers()` | 枚举收发器 | 调试/统计 |
| `createDataChannel(label, init?)` | 创建数据通道 | 任意时刻（本端） |
| `getStats(selector?) → RTCStatsReport` | 取码率/丢包/候选对等统计 | 运行中定期轮询 |
| `getConfiguration()` / `setConfiguration(cfg)` | 读/改 ICE servers 等 | 漫游切换 TURN 时用 |
| `restartIce()` | 重启 ICE（断网切换 Wi-Fi / 蜂窝后调用） | 重连流程 |
| `close()` | 释放所有资源，状态变 closed | 结束通话 |
| `generateCertificate(alg)` **静态** | 预生成 DTLS 证书（见第 7 章） | 会话开始前 |

### 9 个主要事件

| 事件 | 触发时机 |
|---|---|
| `onnegotiationneeded` | Senders/Transceivers/Direction 变化 → 需要重新 O/A；**一定要在 handler 里做去抖 + 状态 guard** |
| `onsignalingstatechange` | signalingState 变 |
| `onicegatheringstatechange` | ICE gathering 状态变 |
| `oniceconnectionstatechange` | ICE 连通状态变（查网络问题最有用） |
| `onconnectionstatechange` | 整体连接状态变（UI 用它展示「已连接/重连中」） |
| `onicecandidate` | ICE 新候选产生 → 走信令发对端（Trickle） |
| `onicecandidateerror` | STUN/TURN 地址某端口探测失败（日志定位用） |
| `ondatachannel` | 对端 createDataChannel → 本端拿到新的 channel |
| `ontrack` | 对端新增入向媒体轨 → 把 `e.streams[0]` 贴到 `<video>` |

### Offer / Answer 建链 8 步（Offer 方）

```ts
// ① 取本地媒体
const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });

// ② 加进 PC（底层等价于 addTransceiver('audio',{direction:'sendrecv'})）
const senders = stream.getTracks().map(t => pc.addTrack(t, stream));

// ③ 注册信令输出事件
pc.onicecandidate       = (e) => e.candidate && signaling.send('ice', e.candidate);
pc.oniceconnectionstatechange = () => console.log(pc.iceConnectionState);
pc.ontrack              = (e) => remoteVideo.srcObject = e.streams[0];

// ④ 生成本地 Offer
const offer = await pc.createOffer({ offerToReceiveAudio: true, offerToReceiveVideo: true });
await pc.setLocalDescription(offer);       // 触发 ICE gathering 开始
signaling.send('offer', pc.localDescription);

// ⑤ 收到对端 Answer
const answerFromSignaling = await signaling.recv('answer');
await pc.setRemoteDescription(answerFromSignaling);

// ⑥ 收到对端 ICE 候选（Trickle 模式下是一条一条 arrive）
for await (const cand of signaling.recvIterable('ice')) {
  await pc.addIceCandidate(cand);
}
```

### RTCConfiguration 完整配置

```ts
interface RTCConfiguration {
  iceServers?: RTCIceServer[];            // 【必填】STUN/TURN 服务器列表
  iceTransportPolicy?:                    // ICE 候选筛选策略
      "all" | "relay";                    //   "relay" = 只走 TURN，用来完全隐藏客户端 IP
  bundlePolicy?:                          // 传输复用策略
      "balanced"                          //   音频一条，视频全合一条（默认）
    | "max-bundle"                        //   全部媒体 + RTCP + DataChannel 复用同一对 5-tuple
    | "max-compat";                       //   完全不复用，向后兼容古老客户端
  rtcpMuxPolicy?: "require";              // 现代浏览器固定 "require"（RTCP 复用 RTP 端口）
  iceCandidatePoolSize?: 0..262143;       // 预收集 N 对候选（0 = setLocalDescription 后才收集）
  certificates?: RTCCertificate[];        // 预生成 DTLS 证书（可跨多次连接复用，握手更快）
}

interface RTCIceServer {
  urls: string | string[];                       // "stun:stun.l.google.com:19302"
  username?: string;                             // TURN 用户名
  credential?: string;                           // TURN 密码（长期凭据机制）
  credentialType?: "password" | "oauth";         // 可选 oauth
}
```

**预生成 DTLS 证书**（静态方法，一次生成反复使用）：
```ts
const cert = await RTCPeerConnection.generateCertificate({
  name: 'RSASSA-PKCS1-v1_5', modulusLength: 2048,
  publicExponent: new Uint8Array([1, 0, 1]), hash: 'SHA-256',
  expires: Date.now() + 7 * 24 * 3600 * 1000,      // 7 天有效期
});
const pc = new RTCPeerConnection({ certificates: [cert] });
```

## RTCDtlsTransport

> DTLS 加密传输层

### 概述

提供 DTLS（Datagram Transport Layer Security）传输信息的访问，用于加密 RTP/RTCP 和 SCTP 数据。

**状态机**：

```
new → connecting → connected → closed
                ↓
             failed
```

### 属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `state` | string | DTLS 状态 |
| `iceTransport` | RTCIceTransport | 底层 ICE 传输 |

### 方法

#### getRemoteCertificates()

获取远程证书链。

```js
const certs = transport.getRemoteCertificates()
// 返回 ArrayBuffer[]
```

**用途**：应用层验证远程身份

### 事件

| 事件 | 说明 |
|------|------|
| `statechange` | 状态变化 |
| `error` | 传输层错误 |

### 使用示例

```js
const dtlsTransport = sender.transport.dtlsTransport;

dtlsTransport.onstatechange = () => {
  console.log('DTLS 状态:', dtlsTransport.state);
  if (dtlsTransport.state === 'failed') {
    handleFailure();
  }
};

// 获取远程证书
const remoteCerts = dtlsTransport.getRemoteCertificates();
```

## RTCIceTransport

> ICE 传输层

### 概述

负责找到两个设备之间的最佳通信路径。

### 状态机

```
┌─────────┐     ┌─────────┐     ┌───────────┐     ┌───────────┐
│   new   │────►│checking │────►│ connected │────►│ completed │
└─────────┘     └─────────┘     └───────────┘     └───────────┘
                                    │                   │
                                    │ 所有候选已考虑      │
                                    ▼                   │
                            ┌──────────────┐             │
                            │ disconnected │             │
                            └──────┬───────┘             │
                                   │ 无法恢复              │
                                   ▼                      │
                            ┌─────────┐                   │
                            │ failed  │◄──────────────────┘
                            └─────────┘
```

**状态说明**：

| 状态 | 说明 |
|------|------|
| `new` | 初始状态 |
| `checking` | 正在检查候选配对 |
| `connected` | 已连接 |
| `completed` | 已完成（稳定） |
| `disconnected` | 临时断开 |
| `failed` | 失败（终态） |
| `closed` | 已关闭 |

### 属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `state` | string | ICE 传输状态 |
| `gatheringState` | string | 收集状态 |
| `component` | string | `rtp` / `rtcp` |
| `role` | string | `controlling` / `controlled` |

### 方法

| 方法 | 说明 |
|------|------|
| `getLocalCandidates()` | 获取本地候选 |
| `getLocalParameters()` | 获取本地参数 |
| `getRemoteCandidates()` | 获取远程候选 |
| `getRemoteParameters()` | 获取远程参数 |
| `getSelectedCandidatePair()` | 获取选中的候选配对 |

### 事件

| 事件 | 说明 |
|------|------|
| `statechange` | 状态变化 |
| `gatheringstatechange` | 收集状态变化 |
| `selectedcandidatepairchange` | 候选配对变化 |

### 使用示例

```js
const iceTransport = sender.transport.iceTransport;

// 监听状态
iceTransport.onstatechange = () => {
  console.log('ICE 状态:', iceTransport.state);
};

// 获取选中的候选配对
const pair = iceTransport.getSelectedCandidatePair();
if (pair) {
  console.log('本地:', pair.local.ip);
  console.log('远程:', pair.remote.ip);
}
```

## RTCSctpTransport

> SCTP 数据通道传输

### 概述

SCTP（Stream Control Transmission Protocol）用于传输 RTCDataChannel 数据。

**获取方式**：`pc.sctp`

### 属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `maxChannels` | number | 最大通道数 |
| `maxMessageSize` | number | 最大消息大小 |
| `state` | string | 传输状态 |
| `transport` | RTCDtlsTransport | 底层 DTLS 传输 |

### 状态机

```
connecting → connected → closed
```

### 使用示例

```js
const sctp = pc.sctp;

// 检查最大消息大小
if (dataSize > sctp.maxMessageSize) {
  // 需要分块传输
  console.log('数据太大，需要分块');
}

// 监听状态
sctp.addEventListener('statechange', () => {
  console.log('SCTP 状态:', sctp.state);
});
```

## 完整流程示例

### 建立连接

```js
const pc = new RTCPeerConnection({
  iceServers: [{ urls: 'stun:stun.l.google.com:19302' }]
});

// 1. 添加本地轨道
const localStream = await navigator.mediaDevices.getUserMedia({ video: true });
localStream.getTracks().forEach(track => {
  pc.addTrack(track, localStream);
});

// 2. 监听远端轨道
pc.ontrack = (event) => {
  remoteVideo.srcObject = event.streams[0];
};

// 3. 创建 Data Channel
const dc = pc.createDataChannel('chat');

// 4. 监听 ICE 候选
pc.onicecandidate = (event) => {
  if (event.candidate) {
    sendToPeer(event.candidate);
  }
};

// 5. 协商
const offer = await pc.createOffer();
await pc.setLocalDescription(offer);
sendToPeer(offer);

// 处理收到的信令
signalingChannel.onmessage = async (msg) => {
  if (msg.type === 'offer') {
    await pc.setRemoteDescription(msg);
    const answer = await pc.createAnswer();
    await pc.setLocalDescription(answer);
    sendToPeer(answer);
  } else if (msg.type === 'answer') {
    await pc.setRemoteDescription(msg);
  } else if (msg.candidate) {
    await pc.addIceCandidate(msg.candidate);
  }
};
```

### 监控连接状态

```js
// ICE 连接状态
pc.oniceconnectionstatechange = () => {
  console.log('ICE 状态:', pc.iceConnectionState);
  
  if (pc.iceConnectionState === 'failed') {
    pc.restartIce();
  }
};

// 连接状态
pc.onconnectionstatechange = () => {
  console.log('连接状态:', pc.connectionState);
};
```
