# WebRTC Encoded Transform 完全指南

> 编码转换 API — 在 Worker 中修改编码后的音视频帧

---

## 概述

WebRTC Encoded Transform API 允许在 WebRTC 连接中修改编码后的媒体帧（音频/视频），实现端到端加密、内容过滤等功能。

**相关接口**：
- `RTCRtpScriptTransform` — 主线程侧，用于插入转换管道
- `RTCRtpScriptTransformer` — Worker 线程侧，提供读写流
- `RTCEncodedAudioFrame` — 编码音频帧
- `RTCEncodedVideoFrame` — 编码视频帧

---

## 工作原理

```
主线程                           Worker 线程
┌─────────────────┐          ┌─────────────────┐
│ RTCRtpScript    │─────────→│ rtctransform    │
│ Transform       │  共享     │ event           │
└─────────────────┘          └────────┬────────┘
                                      │
                              ┌───────▼───────┐
                              │ RTCRtpScript  │
                              │ Transformer   │
                              │ (readable +   │
                              │  writable)    │
                              └───────┬───────┘
                                      │
                         ┌────────────▼────────────┐
                         │ TransformStream 处理     │
                         │ (编码帧转换逻辑)          │
                         └─────────────────────────┘
```

---

## 接口对比

| 接口 | 线程 | 职责 |
|------|------|------|
| `RTCRtpScriptTransform` | 主线程 | 创建转换管道并插入到 RTCPeerConnection |
| `RTCRtpScriptTransformer` | Worker 线程 | 提供读写流和处理编码帧 |
| `RTCEncodedAudioFrame` | Worker 线程 | 编码音频帧（可访问/修改数据） |
| `RTCEncodedVideoFrame` | Worker 线程 | 编码视频帧（可访问/修改数据） |

## RTCRtpScriptTransform（主线程）

> 用于将转换管道插入到 WebRTC 发送或接收管道中

### 构造函数

```js
new RTCRtpScriptTransform(worker, options, transferList)
```

**参数**：
- `worker`：运行转换代码的 Worker 对象
- `options`（可选）：传递给 Worker 的选项对象
- `transferList`（可选）：可转移对象数组

### 使用方法

#### 添加到发送管道

```js
const worker = new Worker("worker.js");
sender.transform = new RTCRtpScriptTransform(worker, {
  name: "senderTransform"
});
```

#### 添加到接收管道

```js
const worker = new Worker("worker.js");
receiver.transform = new RTCRtpScriptTransform(worker, {
  name: "receiverTransform"
});
```

### 插入位置

| 属性 | 说明 |
|------|------|
| `RTCRtpSender.transform` | 编码后、发送前处理 |
| `RTCRtpReceiver.transform` | 接收后、解码前处理 |

## RTCRtpScriptTransformer（Worker 线程）

> 在 Worker 中提供处理编码帧的能力

### 属性

#### readable — 可读流

用于从 WebRTC 管道读取编码帧。

```js
transformer.readable  // ReadableStream
```

#### writable — 可写流

用于写入处理后的编码帧。

```js
transformer.writable  // WritableStream
```

#### options — 配置选项

从 `RTCRtpScriptTransform` 构造函数传递的选项。

```js
transformer.options  // object
```

### 方法

#### generateKeyFrame()

请求视频编码器生成关键帧（发送端使用）。

```js
await transformer.generateKeyFrame()
```

#### sendKeyFrameRequest()

请求发送端发送关键帧（接收端使用）。

```js
await transformer.sendKeyFrameRequest()
```

## rtctransform 事件

当编码帧进入 WebRTC 编码转换队列时，在 Worker 的 DedicatedWorkerGlobalScope 上触发此事件。

### 事件语法

```js
// 方式1：addEventListener
addEventListener("rtctransform", (event) => { })

// 方式2：onrtctransform
onrtctransform = (event) => { }
```

### 触发时机

1. 创建关联的 `RTCRtpScriptTransform` 时
2. 新的编码视频或音频帧被加入处理队列时

### 浏览器支持

- Chrome 96+
- Firefox 98+
- Safari 不支持

### 与 RTCTransformEvent 的关系

`rtctransform` 事件的事件类型即为 `RTCTransformEvent`，继承自 `Event` 接口。

## RTCEncodedAudioFrame

> 编码音频帧 — 可访问和修改音频编码数据

### 属性

#### data — 编码帧数据

返回包含编码帧数据的缓冲区，可修改后重新入队。

```js
frame.data  // ArrayBuffer
```

#### timestamp — 时间戳（已废弃）

> ⚠️ **已废弃**：请使用 `getMetadata().captureTime` 替代。

### 方法

#### getMetadata() — 获取元数据

```js
const metadata = frame.getMetadata()
```

**返回对象属性**：

| 属性 | 类型 | 说明 |
|------|------|------|
| `audioLevel` | number | 音频级别（0~1），0 表示静音 |
| `captureTime` | DOMHighResTimeStamp | 帧采集时间 |
| `contributingSources` | Array | 贡献源 SSRC 列表（混音场景） |
| `mimeType` | string | 编码格式，如 "audio/opus" |
| `payloadType` | number | RTP 载荷类型（0~127） |
| `receiveTime` | DOMHighResTimeStamp | 最后接收包的时间 |
| `rtpTimestamp` | number | RTP 时间戳 |
| `sequenceNumber` | number | 序列号（仅入站帧） |

## RTCEncodedVideoFrame

> 编码视频帧 — 可访问和修改视频编码数据

### 属性

#### type — 帧类型

```js
frame.type  // "key" | "delta"
```

| 值 | 含义 |
|----|------|
| `"key"` | 关键帧，包含完整图像信息，可独立解码 |
| `"delta"` | 增量帧，包含相对变化，需依赖其他帧 |

#### data — 编码帧数据

返回包含编码帧数据的缓冲区，可修改后重新入队。

```js
frame.data  // ArrayBuffer
```

#### timestamp — 时间戳（已废弃）

> ⚠️ **已废弃**：请使用 `getMetadata().rtpTimestamp` 替代。

### 方法

#### getMetadata() — 获取元数据

```js
const metadata = frame.getMetadata()
```

**返回对象属性**：

| 属性 | 类型 | 说明 |
|------|------|------|
| `contributingSources` | Array | 贡献源 SSRC 列表 |
| `dependencies` | Array | 依赖的帧 ID（关键帧为空） |
| `frameId` | number | 帧 ID |
| `height` | number | 视频高度（最大 65535） |
| `mimeType` | string | 编码格式，如 "video/VP8" |
| `payloadType` | number | RTP 载荷类型（0~127） |
| `receiveTime` | DOMHighResTimeStamp | 最后接收包的时间 |
| `rtpTimestamp` | number | RTP 时间戳 |
| `spatialIndex` | number | 空间层索引（可分层编码） |
| `synchronizationSource` | number | 同步源 SSRC |
| `temporalIndex` | number | 时间层索引（可分层编码） |
| `width` | number | 视频宽度（最大 65535） |

## 视频编码基础

```
原始视频 → 视频编码器 → 压缩码流 → 网络传输

编码过程：
┌─────────────┐
│  关键帧 (I) │ ←── 完整图像，可独立解码
└─────────────┘
       ↓
┌─────────────┐
│  增量帧 (P) │ ←── 仅存储与关键帧的差异
└─────────────┘
```

**关键帧 vs 增量帧**：

| 类型 | 大小 | 独立性 | 用途 |
|------|------|--------|------|
| 关键帧 | 大 | 可独立解码 | 视频开头、切换、seek |
| 增量帧 | 小 | 依赖关键帧 | 节省带宽 |

## 完整示例

### 主线程

```js
const stream = await navigator.mediaDevices.getUserMedia({ video: true });
const [track] = stream.getTracks();
const sender = peerConnection.addTrack(track, stream);

const worker = new Worker("worker.js");
sender.transform = new RTCRtpScriptTransform(worker, {
  name: "senderTransform"
});
```

### Worker 线程

```js
// worker.js
self.onrtctransform = (event) => {
  const transformer = event.transformer;
  
  const transform = new TransformStream({
    transform(encodedFrame, controller) {
      // 根据帧类型处理
      if (encodedFrame.type === "key") {
        console.log('处理关键帧');
      }
      
      // 示例：位反转加密
      const view = new DataView(encodedFrame.data);
      const newData = new ArrayBuffer(encodedFrame.data.byteLength);
      const newView = new DataView(newData);

      for (let i = 0; i < encodedFrame.data.byteLength; ++i) {
        newView.setInt8(i, ~view.getInt8(i) & 0xff);
      }

      encodedFrame.data = newData;
      controller.enqueue(encodedFrame);
    }
  });
  
  transformer.readable
    .pipeThrough(transform)
    .pipeTo(transformer.writable);
};
```

## 关键帧机制

### 为什么需要关键帧？

```
关键帧 (Key Frame)          Delta 帧
┌─────────────────┐       ┌─────────────┐
│ 完整图像信息     │       │ 仅包含变化   │
│ 可独立解码       │ ───→ │ 依赖前帧     │
└─────────────────┘       └─────────────┘
```

### 关键帧使用场景

1. **新参与者加入**：需要关键帧才能开始显示视频
2. **加密传输**：接收方需要关键帧才能解密后续帧
3. **丢包严重**：请求关键帧重新开始

### 代码示例

```js
// 接收端请求发送端发送关键帧
addEventListener("rtctransform", async (event) => {
  const transformer = event.transformer;
  
  if (needsKeyFrame(transformer.options)) {
    await transformer.sendKeyFrameRequest();
  }
  
  // 继续处理...
  event.transformer.readable
    .pipeThrough(new TransformStream(transformFn))
    .pipeTo(event.transformer.writable);
});
```
