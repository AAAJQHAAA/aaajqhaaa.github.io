## 一、音视频基础概念

### 1.1 单位换算

- `bit`（比特/位）：0 或 1，数据传输的最小单位
- `byte`（字节）：1 byte = 8 bit，数据存储的基础单位
- `1 KB = 1024 byte`，`1 MB = 1024 KB`，`1 GB / TB / PB / EB` 依次 ×1024

> 注意区分：`b` 表示 bit（传输速率常用），`B` 表示 byte（文件大小常用）。

### 1.2 视频核心参数

| 参数 | 含义 | 影响 |
| --- | --- | --- |
| 分辨率 | 图像像素数，如 1920×1080 | 画面精细度 |
| 帧率 FPS | 每秒刷新的帧数，如 25/30/60 | 流畅度（≥25 人眼基本感觉连续） |
| 码流/码率 | 单位时间数据流量，单位 kb/s 或 Mb/s | 画质（同分辨率下码率越大画质越好） |
| 位深 | 每个像素用多少 bit 保存颜色 | 色彩精度 |

**码流估算公式**（以 1920×1080，YUV420，30FPS 为例）：

```
码流 = 1920 × 1080 × (3/2) × 8 × 30 / (1024×1024) ≈ 89 Mb/s
```

- YUV420 每帧大小 = 分辨率 × 3/2（与存储格式相关）
- RGB24 每帧大小 = 分辨率 × 3；RGB32 = 分辨率 × 4

### 1.3 音频核心参数

| 参数 | 含义 | 常见值 |
| --- | --- | --- |
| 采样率 | 每秒采样次数（Hz） | 8000（电话）、44100（CD）、48000（DVD/专业） |
| 位深 | 每个采样点用多少 bit 保存 | 16 bit（CD，约 96dB 动态范围）、24 bit |
| 声道数 | 音源/输出通道数 | 1（单声道）、2（立体声） |
| 比特率 | 每秒传送的 bit 数（bps） | = 采样率 × 位深 × 声道数 |

**比特率计算示例**：44.1kHz / 16bit / 双声道

```
比特率 = 44100 × 16 × 2 = 1411200 bps ≈ 1378 kbps
每秒数据量 = 1411200 / 8 = 176400 byte
```

### 1.4 PCM（脉冲编码调制）

- PCM 是一种**模拟信号数字化方法**，不是格式。最常见的 PCM 存储格式是 WAV。
- PCM 数据质量/体积由三个因素决定：**采样率 + 位深 + 声道数**
- 体积公式：`SampleRate × bitDepth × channelCounts`

### 1.5 分辨率补充

- **显示器分辨率**：显示器物理分辨率（如 1920×1080）
- **屏幕分辨率（显示分辨率）**：可设置，≤ 显示器分辨率
- **图像分辨率**：图像本身的像素数目

## 三、Media Capabilities API

> 检测浏览器设备对指定媒体配置（编解码器、比特率、帧率、采样率）的支持情况，替代了 `MediaSource.isTypeSupported()` 和 `HTMLMediaElement.canPlayType()`。

文档：https://developer.mozilla.org/en-US/docs/Web/API/Media_Capabilities_API

### 3.1 核心 API

```ts
interface MediaCapabilities {
  // 是否支持解码对应媒体配置
  decodingInfo(configuration: MediaDecodingConfiguration): Promise<MediaCapabilitiesDecodingInfo>;
  // 是否支持编码对应媒体配置
  encodingInfo(configuration: MediaEncodingConfiguration): Promise<MediaCapabilitiesEncodingInfo>;
}
```

返回结果包含三个布尔字段：`supported`（是否支持）、`smooth`（是否流畅）、`powerEfficient`（是否省电）。

### 3.2 解码能力检测示例

```js
if ("mediaCapabilities" in navigator) {
  const videoConfiguration = {
    type: "file", // file | media-source | webrtc
    video: {
      contentType: "video/webm;codecs=vp8",
      width: 800,
      height: 600,
      bitrate: 10000,   // 比特率 bps
      framerate: 30,    // 帧率
    },
  };

  navigator.mediaCapabilities.decodingInfo(videoConfiguration).then((result) => {
    console.log(`supported: ${result.supported}`);
    console.log(`smooth: ${result.smooth}`);
    console.log(`powerEfficient: ${result.powerEfficient}`);
  });
}
```

### 3.3 编码能力检测示例

```js
const mediaConfig = {
  type: "record", // record | transmission
  video: {
    contentType: "video/webm;codecs=vp8.0",
    width: 1920,
    height: 1080,
    bitrate: 120000,
    framerate: 48,
  },
};

navigator.mediaCapabilities.encodingInfo(mediaConfig).then((result) => {
  console.log(result.supported, result.smooth, result.powerEfficient);
});
```

## 四、Media Capture and Streams API

> 提供获取媒体流（摄像头/麦克风/屏幕）、处理流的相关接口。


```js
const stream = await navigator.mediaDevices.getUserMedia({
  video: { width: { min: 640, ideal: 1920, max: 1920 }, height: { ideal: 1080 } },
  audio: { echoCancellation: true, noiseSuppression: true },

```

#### 获取屏幕共享流

```js
const stream = await navigator.mediaDevices.getDisplayMedia({
  video: true,
  audio: false,

```

#### 枚举设备

```js
navigator.mediaDevices.enumerateDevices().then((devices) => {
  devices.forEach((device) => {
    // device.kind: "audioinput" | "audiooutput" | "videoinput"

  });

```

### 4.2 MediaStream（媒体流）

```ts

```

### 4.3 MediaStreamTrack（媒体流轨道）

```ts
interface MediaStreamTrack extends EventTarget {
  readonly id: string;
  readonly kind: string;          // "audio" | "video"
  readonly label: string;         // 轨道来源标识
  readonly muted: boolean;        // 是否因技术问题无法提供数据
  readonly readyState: "ended" | "live";

  getConstraints(): MediaTrackConstraints;
  getSettings(): MediaTrackSettings;

```

#### 约束（constraints）类型说明

```text
ConstrainDouble  / ConstrainULong : { max, min, exact, ideal }  最大/最小/必须/期望
ConstrainDOMString / ConstrainBoolean : { exact, ideal }         可接受/期望
优先级：exact > ideal，无法满足 exact 则报错
```

#### 动态切换摄像头示例

```js
function switchCameras(track, camera) {
  const constraints = track.getConstraints();
  constraints.facingMode = camera; // "user"(前置) | "environment"(后置)
  track.applyConstraints(constraints);
}
```

## 五、MediaStream Recording API

> 录制媒体流，生成 Blob 数据。

文档：https://developer.mozilla.org/en-US/docs/Web/API/MediaStream_Recording_API

### 5.1 MediaRecorder 接口

```ts
interface MediaRecorder extends EventTarget {
  readonly mimeType: string;
  readonly state: "inactive" | "recording" | "paused";
  readonly stream: MediaStream;
  readonly audioBitsPerSecond: number;
  readonly videoBitsPerSecond: number;
  start(timeslice?: number): void;   // 开启录制，timeslice 毫秒
  stop(): void;                       // 停止录制，触发 dataavailable
  pause(): void;
  resume(): void;
  requestData(): void;                // 触发 dataavailable 事件
  ondataavailable / onerror / onpause / onresume / onstart / onstop: 事件;
}

declare var MediaRecorder: {
  new(stream: MediaStream, options?: MediaRecorderOptions): MediaRecorder;
  isTypeSupported(type: string): boolean;  // 是否支持该 MIME 类型
};

// options: { mimeType, audioBitsPerSecond, videoBitsPerSecond, bitsPerSecond }
```

### 5.2 录音示例

```js
// 1. 获取麦克风流
const stream = await navigator.mediaDevices.getUserMedia({ audio: true });

// 2. 创建录制器
const mediaRecorder = new MediaRecorder(stream);
const chunks = [];

mediaRecorder.ondataavailable = (e) => {
  chunks.push(e.data);
};

mediaRecorder.onstop = () => {
  const blob = new Blob(chunks, { type: "audio/ogg; codecs=opus" });
  const audioURL = URL.createObjectURL(blob);
  audio.src = audioURL;
};

// 3. 开始/停止
recordBtn.onclick = () => mediaRecorder.start();
stopBtn.onclick = () => mediaRecorder.stop();
```

### 5.3 录屏并下载示例

```js
const stream = await navigator.mediaDevices.getDisplayMedia({ video: true });
const mediaRecorder = new MediaRecorder(stream, { mimeType: "video/webm; codecs=vp9" });
const recordedChunks = [];

mediaRecorder.ondataavailable = (event) => {
  if (event.data.size > 0) {
    recordedChunks.push(event.data);
    const blob = new Blob(recordedChunks, { type: "video/webm" });
    const url = URL.createObjectURL(blob);
    const a = document.createElement("a");
    a.href = url;
    a.download = "record.webm";
    a.click();
    URL.revokeObjectURL(url);
  }
};

mediaRecorder.start();
setTimeout(() => mediaRecorder.stop(), 9000); // 9 秒后停止
```

### 5.4 检查 MIME 类型支持

```js
["video/webm", "video/webm;codecs=vp8", "video/webm;codecs=h264", "audio/webm;codecs=opus"].forEach(
  (type) => console.log(`${type}: ${MediaRecorder.isTypeSupported(type)}`)
```

## 六、Web Audio API

> 用于操作、修改声音。工作流程：`音频源节点 → 操作节点 → 目标节点`（Input → effects → destination）。

文档：https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API

### 6.1 AudioContext（音频上下文）

```ts
interface AudioContext extends BaseAudioContext {
  readonly baseLatency: number;      // 延迟
  readonly outputLatency: number;    // 输出延迟（秒）
  suspend(): Promise<void>;          // 暂停
  resume(): Promise<void>;           // 恢复
  close(): Promise<void>;            // 关闭
  // 【声源节点】从 DOM 标签获取声源
  createMediaElementSource(mediaElement: HTMLMediaElement): MediaElementAudioSourceNode;
  // 【声源节点】从流获取声源
  createMediaStreamSource(mediaStream: MediaStream): MediaStreamAudioSourceNode;
  // 【目标节点】创建目标节点（输出 MediaStream）
  createMediaStreamDestination(): MediaStreamAudioDestinationNode;
  getOutputTimestamp(): AudioTimestamp;
}

// 构造：new AudioContext({ latencyHint: "balanced"|"interactive"|"playback", sampleRate? })
```

### 6.2 BaseAudioContext 关键方法

```ts
interface BaseAudioContext extends EventTarget {
  readonly audioWorklet: AudioWorklet;       // 音频工作台（加载模块）

  readonly sampleRate: number;
  readonly state: "closed" | "running" | "suspended";

  // —— 声源节点 ——

  createBiquadFilter(): BiquadFilterNode;             // 双二阶滤波器
  createIIRFilter(feedforward, feedback): IIRFilterNode;
  createDelay(maxDelayTime?): DelayNode;              // 延迟
  createConvolver(): ConvolverNode;                   // 混响
  createDynamicsCompressor(): DynamicsCompressorNode; // 压缩
  createPanner(): PannerNode;                         // 3D 空间化
  createStereoPanner(): StereoPannerNode;             // 立体声
  createWaveShaper(): WaveShaperNode;                 // 非线性失真
  createChannelMerger(numberOfInputs?): ChannelMergerNode;
  createChannelSplitter(numberOfOutputs?): ChannelSplitterNode;

  // —— 数据 ——
  createBuffer(numberOfChannels, length, sampleRate): AudioBuffer;
  decodeAudioData(audioData: ArrayBuffer): Promise<AudioBuffer>; // ArrayBuffer → AudioBuffer(PCM)

  onstatechange: 事件;
}
```

### 6.3 常用节点说明

| 节点 | 作用 | 关键属性/方法 |
| --- | --- | --- |
| OscillatorNode | 周期波形（声源） | `type`："sine"(默认)/"square"/"sawtooth"/"triangle"；`frequency` 默认 440 |
| GainNode | 音量控制 | `gain`（AudioParam） |
| AnalyserNode | 频谱/波形可视化 | `fftSize` 默认 2048；`getByteFrequencyData()`、`getByteTimeDomainData()` |
| BiquadFilterNode | 滤波器 | `type`："lowpass"/"highpass"/"bandpass"/"notch" 等 |
| DynamicsCompressorNode | 压缩（降低响亮部分） | `threshold`、`ratio`、`attack`、`release` |
| AudioBufferSourceNode | 播放 PCM 数据 | `buffer`、`loop`、`start()` |

### 6.6 AudioWorklet（自定义音频处理）

用于取代已废弃的 `ScriptProcessorNode`，在独立线程处理音频。

**主线程：加载模块 + 创建节点**

```ts
// 1. 加载 worklet 模块
await audioCtx.audioWorklet.addModule("processor.js");

// 2. 创建节点
const node = new AudioWorkletNode(audioCtx, "audio-data-get");

// 3. 接收处理器发来的数据
node.port.onmessage = (e) => {
  console.log("PCM 数据", e.data);
};
```

**processor.js（worklet 线程：注册处理器）**

```js
class AudioDataGetWorkletProcessor extends AudioWorkletProcessor {
  process(inputList, outputList, parameters) {
    // inputList/outputList：128 采样帧的数组
    if (inputList.length > 0 && inputList[0].length > 0) {
      this.port.postMessage(inputList[0]); // 把输入数据发给主线程
    }
    return true; // 保持活跃
  }
}
registerProcessor("audio-data-get", AudioDataGetWorkletProcessor);
```

## 八、WebRTC

> WebRTC（Web Real-Time Communication）实现浏览器间 P2P 实时通信（音视频 + 数据）。

文档：https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API

### 8.1 核心概念

#### ICE（互动式连接建立）

ICE 是浏览器实现 P2P 连接的**框架**，用于在两台设备间建立直接连接。由于防火墙、NAT 等原因，直接连接通常不可行，需要借助 STUN/TURN 服务器。

#### STUN（获取设备公共地址）

- Session Traversal Utilities for NAT
- 客户端向 STUN 服务器请求，获取自己的**公共 IP 地址**及 NAT 限制信息
- 用于帮助对端找到自己

#### NAT（网络地址转换）

- 路由器有一个公共 IP，连接到路由器的设备使用私有 IP
- 请求通过唯一端口从私有 IP 转换为路由器的公共 IP
- 部分路由器（Symmetric NAT）会限制谁能连接内网设备，此时需要 TURN

#### TURN（中转数据）

- Traversal Using Relays around NAT
- 当 STUN 无法穿透（如 Symmetric NAT）时，通过 TURN 服务器**中继所有数据**
- 开销较大，仅在没有其他选择时使用

#### SDP（会话描述协议）

- Session Description Protocol，用于描述连接的多媒体内容（分辨率、格式、编解码器、加密等）
- 本质是描述连接的**元数据**，不是真正的协议
- 由多行 UTF-8 文本组成，每行格式：`类型=值`，如 `v=`（版本）、`o=`（发起方）、`s=`（会话名）、`m=`（媒体描述）、`a=`（属性行）

### 8.2 RTCPeerConnection（核心 API）

> 本地与远端计算机之间的 WebRTC 连接，提供连接、维护、监视、关闭的方法。

```ts
interface RTCPeerConnection extends EventTarget {
  // —— 状态 ——
  readonly connectionState: "closed"|"connected"|"connecting"|"disconnected"|"failed"|"new";
  readonly iceConnectionState: "checking"|"closed"|"completed"|"connected"|"disconnected"|"failed"|"new";
  readonly iceGatheringState: "complete"|"gathering"|"new";
  readonly signalingState: "closed"|"have-local-offer"|"have-remote-offer"|"stable";

  // —— 会话描述 ——
  readonly localDescription: RTCSessionDescription | null;
  readonly remoteDescription: RTCSessionDescription | null;

  // —— 媒体轨道 ——
  addTrack(track: MediaStreamTrack, ...streams: MediaStream[]): RTCRtpSender;
  removeTrack(sender: RTCRtpSender): void;
  getSenders(): RTCRtpSender[];
  getReceivers(): RTCRtpReceiver[];
  getTransceivers(): RTCRtpTransceiver[];

  // —— 协商 ——
  createOffer(options?): Promise<RTCSessionDescriptionInit>;   // 创建 Offer SDP
  createAnswer(options?): Promise<RTCSessionDescriptionInit>;  // 创建 Answer SDP
  setLocalDescription(description?): Promise<void>;            // 设置本地描述
  setRemoteDescription(description: RTCSessionDescriptionInit): Promise<void>; // 设置远端描述

  // —— ICE ——
  addIceCandidate(candidate?: RTCIceCandidateInit): Promise<void>;  // 添加远端 ICE 候选
  restartIce(): void;                                                 // 重新收集 ICE 候选

  // —— 数据通道 ——
  createDataChannel(label: string, dataChannelDict?): RTCDataChannel;

  // —— 其他 ——
  close(): void;
  getConfiguration(): RTCConfiguration;
  setConfiguration(configuration?: RTCConfiguration): void;
  getStats(selector?): Promise<RTCStatsReport>;

  // —— 事件 ——
  onconnectionstatechange / onicecandidate / onicecandidateerror
  oniceconnectionstatechange / onicegatheringstatechange
  onnegotiationneeded / onsignalingstatechange / ontrack / ondatachannel;
}

// 构造：new RTCPeerConnection(configuration?: RTCConfiguration)
```

### 8.4 关键事件说明

| 事件 | 触发时机 |
| --- | --- |
| `onicecandidate` | 收集到本地 ICE 候选，需通过信令服务器传给远端 |
| `ontrack` | 远端添加媒体轨道，可播放远端音视频 |
| `ondatachannel` | 远端创建数据通道时触发 |
| `onnegotiationneeded` | 会话协商需要更改时触发（如添加轨道后） |
| `onconnectionstatechange` | 连接状态变化 |

### 8.5 简单连接流程（信令需自备）

```js
const pc = new RTCPeerConnection(configuration);

// 1. 添加本地媒体流
localStream.getTracks().forEach((track) => pc.addTrack(track, localStream));

// 2. 收到本地 ICE 候选 → 通过信令发给远端
pc.onicecandidate = (e) => {
  if (e.candidate) signaling.send({ candidate: e.candidate });
};

// 3. 收到远端轨道 → 播放
pc.ontrack = (e) => {
  remoteVideo.srcObject = e.streams[0];
};

// === 呼叫端（Offer） ===
const offer = await pc.createOffer();
await pc.setLocalDescription(offer);
signaling.send({ offer });                       // 通过信令发给远端

// === 被叫端（Answer） ===
// 收到 offer：
await pc.setRemoteDescription(new RTCSessionDescription(offer));
const answer = await pc.createAnswer();
await pc.setLocalDescription(answer);
signaling.send({ answer });

// === 呼叫端收到 answer ===
await pc.setRemoteDescription(new RTCSessionDescription(answer));

// === 双方收到对方 ICE 候选 ===
// signaling.on('candidate', ({candidate}) => pc.addIceCandidate(candidate));
```

## 九、音视频编码与 ffmpeg

### 9.1 编码概念

**为什么要编码**：原始音视频数据体积巨大，编码可大幅压缩，便于存储和传输。

#### 视频编码

- **H.26X 系列**：H.264（主流）、H.265/HEVC、H.266
- **MPEG 系列**：MPEG-2、MPEG-4（AVC）
- H.264 帧类型：**I 帧**（关键帧，独立解码）、**P 帧**（前向预测）、**B 帧**（双向预测）

#### 视频编码原理（去除冗余）

- 空间冗余（相邻像素相似）
- 时间冗余（相邻帧相似）
- 编码冗余 / 视觉冗余 / 知识冗余

#### 音频编码

- **压缩编码**：压缩掉冗余信号
- 常见编码器：**opus**（WebRTC 推荐）、**aac**、mp3
- 音频压缩原理：**频率遮蔽**、**时域遮蔽**
- AAC 两种封装：
  - **ADIF**：音频数据交换格式（文件，明确开头）
  - **ADTS**：音频数据传输流（有同步字，可从任意帧处播放）

#### 视频封装容器（文件格式）

包裹音视频编码数据的容器，常见：**MP4、FLV、TS、M3U8、AVI**。不同封装支持的编码不同。

#### 硬解码 vs 软解码

- **硬解码**：利用专用芯片加速（兼容性问题）
- **软解码**：利用 CPU 计算能力解码

### 9.4 ffmpeg 常用命令

#### 基础

```bash
ffmpeg -version              # 查看版本
ffplay -i xxx.mp4            # 播放
ffmpeg -i xxx.mp4            # 查看文件信息
```

#### 格式转换（不改编码）

```bash
ffmpeg -i xxx.mp4 -c copy -f flv xxx.flv
# -i xxx.mp4   输入文件
# -c copy      编解码格式不变
# -f flv       封装格式转换为 flv
```

#### 通用选项

| 选项 | 说明 |
| --- | --- |
| `-f fmt` | 强制采用格式 fmt |
| `-i filename` | 输入文件 |
| `-y` | 覆盖输出文件 |
| `-t 10` | 设置记录时长（秒） |
| `-ss 10` | 从指定时间点开始 |
| `-target xxx` | 设置文件类型（vcd/svcd/dvd） |
| `-hq` | 激活高质量设置 |

#### 视频选项

| 选项 | 说明 |
| --- | --- |
| `-b xxx` | 设置比特率，默认 200kb/s |
| `-r xxx` | 设置帧率，默认 25 |
| `-s 1920X1080` | 设置帧大小 |
| `-aspect 4:3` | 设置横纵比 |
| `-vn` | 不做视频记录 |
| `-vcodec xxx` | 强制使用 codec 编解码（copy 表示原样拷贝） |
| `-maxrate / -minrate xxx` | 最大/最小视频码率 |
| `-bufsize xxx` | 码率控制缓冲区大小 |

#### 音频选项

| 选项 | 说明 |
| --- | --- |
| `-ab xxx` | 设置音频码率 |
| `-ar xxx` | 设置音频采样率 |
| `-ac xxx` | 设置通道数，默认 1 |
| `-an` | 不使用音频 |
| `-acodec xxx` | 使用 codec 编解码 |

#### 两遍编码（提高质量）

```bash
# 第一遍生成统计信息
ffmpeg -i input.mp4 -pass 1 -c:v libx264 -b:v 1000k -f mp4 /dev/null
# 第二遍生成精确码率
ffmpeg -i input.mp4 -pass 2 -c:v libx264 -b:v 1000k output.mp4
```

### 音频基本概念

- **频率**：音调
- **振幅**：响度/音量

```
解协议（http/rtmp） → 解封装（mp4/ts/flv/avi） → 解码（aac/mp3/h264） → 音视频同步
```

- `fltp`：32 位浮点型采样格式
- `stereo`：立体声（双声道）
