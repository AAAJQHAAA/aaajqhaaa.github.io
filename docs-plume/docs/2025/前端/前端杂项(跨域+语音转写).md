# 前端杂项（跨域 + 语音转写）

---

## 一、浏览器跨域访问问题

### 原因
浏览器"同源政策"：协议、IP、端口有一个不同就跨域，浏览器拦截响应。
- 不受跨域影响的标签：`<script src>`、`<img src>`、`<iframe src>`

### 解决方案

#### 方案一：JSONP
利用 `<script>` 标签不受跨域限制的特性。
- 要求：请求URL传回调方法名 `?callback=xxx`，服务端返回 `xxx(data)` 格式
- 缺点：只支持 GET 请求

#### 方案二：后端 CORS（推荐）
```java
// Spring 注解方式
@CrossOrigin("https://example.com")  // 用在Controller类或方法上
```
或实现 Filter 接口，在响应头中添加：
```
Access-Control-Allow-Origin: *                    // 允许跨域的域名
Access-Control-Allow-Credentials: true             // 允许携带Cookie
Access-Control-Allow-Methods: GET,POST,PUT,DELETE  // 允许的请求类型
Access-Control-Allow-Headers: Content-Type          // 允许的请求头
Access-Control-Max-Age: 1800                         // 预检结果缓存时间
```

#### 方案三：代理（开发/部署常用）
**Nginx 代理**
```nginx
http {
    server {
        listen 80;
        location / {
            proxy_pass http://localhost:8080;     # 前端
        }
        location /api {
            proxy_pass http://localhost:8081;     # 后端
        }
    }
}
```
浏览器认为是从 `localhost:80` 访问 `localhost:80/api` → 同源，实际 Nginx 转发到不同端口。

**Node 代理**：发请求到 Node 服务器，Node 转发到后端。

## 二、H5 实现语音转写

### PCM 编码核心概念
- **采样率 SampleRate（Hz）**：每秒采集多少个点（浏览器 `audioContext.sampleRate` 不可更改）
- **位深（bits）**：8位→范围0-255；16位→范围-32768到32767（1字节=8位）
- **声道 channel**：浏览器API获取的PCM数据是**非交错的32位线性PCM**，范围[-1,1]

### 转换步骤

1. **录音过程**（获取PCM采样数组）
   - `AudioWorkletNode`：每次固定128个采样点触发 `process`
   - `ScriptProcessorNode`（已废弃）：可自定义采样点数量触发 `onaudioprocess`
   - 最终得到PCM[-1,1]的采样点数组

2. **采样率转换**
   - 浏览器采样率（如44100Hz）→ 目标采样率（如16000Hz）
   - 减少比例 = 44100/16000 ≈ 3，即每3个相邻采样点取1个

3. **采样点数组转Byte数组**
   - 8位存储：PCM[-1,1] → [0,255]（负数×128+128，正数×127+128），存1字节
   - 16位存储：PCM[-1,1] → [-32768,32767]（负数×32768，正数×32767），存2字节

4. **播放PCM数据**
   - 添加WAV头信息（44字节）即可播放
