STUN-TURN 服务器

一、生产环境实际选择

方案适用场景成本运维复杂度推荐度
自建 coturn中大型项目、流量可控服务器 + 带宽中★★★★★ 事实标准
托管式服务(Twilio NAT Traversal / Xirsys / Cloudflare TURN)小项目、快速上线按流量计费低★★★★
仅用免费 Google STUN内网/LAN 测试00★ 仅测试用
完全不用mediasoup SFU LAN 场景00★★★ 同网段可用

实际生产 90% 的团队选择 自建 coturn,原因:开源、稳定、支持 STUN+TURN 一体、可水平扩展、不按流量计费。

二、为什么是 coturn?

coturn 是目前事实上的 STUN/TURN 实现标准:

  • C 语言实现,性能高,单机可承载数千路并发
  • 同时支持 STUN(RFC 5389)+ TURN(RFC 5766)+ TURN-over-TLS(RFC 7350)
  • 支持 UDP / TCP / TLS-over-TCP 三种传输
  • 支持 long-term credential 机制(可对接业务系统下发临时凭证)
  • 开源(GitHub: coturn/coturn),各大厂内部基本都用它或基于它改造

三、自建 coturn 生产部署

1. 环境准备

项要求
公网服务器推荐 Ubuntu 22.04 / Debian 12,2C4G 起步
公网 IP必须独立(不能共享 NAT)
域名用于 TLS 证书(建议 Let's Encrypt)
开放端口3478/5349(TCP+UDP)、49152–65535(UDP relay)

2. 安装

# Ubuntu / Debian
apt update
apt install -y coturn

# 启用守护进程
sed -i 's/#TURNSERVER_ENABLED=1/TURNSERVER_ENABLED=1/' /etc/default/coturn

3. 生产配置(/etc/turnserver.conf)

# 监听端口
listening-port=3478
tls-listening-port=5349

# 监听所有网卡
listening-ip=0.0.0.0

# 你的公网 IP(必填,否则 relay 地址错误)
external-ip=47.xxx.xxx.xxx

# Realm(必须与生成用户凭证时一致)
realm=turn.yourdomain.com

# 服务器名(可选)
server-name=turn.yourdomain.com

# 数据库(生产用 Redis/MySQL,小规模可用 SQLite)
userdb=/var/lib/turn/turndb

# 凭证机制:long-term(标准 WebRTC 鉴权)
lt-cred-mech

# 短期凭证(推荐,适用于浏览器场景)
# use-turn-session-traffic-stat

# 指纹校验(STUN 消息完整性)
fingerprint

# 中继端口范围(必须开放防火墙)
min-port=49152
max-port=65535

# TLS 证书(Let's Encrypt)
cert=/etc/letsencrypt/live/turn.yourdomain.com/cert.pem
pkey=/etc/letsencrypt/live/turn.yourdomain.com/privkey.pem
cipher-list="HIGH"

# 日志
log-file=/var/log/turn/turnserver.log
simple-log

# 安全:禁止 CLI
no-cli

# 限制单用户带宽(可选,防滥用)
# bps-capacity=0
# total-quota=100

# 禁止回环/私有地址作 relay
no-loopback-peers
no-multicast-peers

4. 生成用户凭证

长期凭证(静态):

turnadmin -k -u alice -r turn.yourdomain.com -p "强密码"
# 输出 key,写入 userdb

短期凭证(推荐,业务系统动态下发):

// Node.js 生成临时凭证(HMAC-SHA1)
const crypto = require('crypto');

function generateTurnCredential(username, secret, ttl = 3600) {
  const expires = Math.floor(Date.now() / 1000) + ttl;
  const hmac = crypto.createHmac('sha1', secret)
    .update(`${expires}:${username}`)
    .digest('base64');
  return {
    username: `${expires}:${username}`,  // 必须以时间戳开头
    credential: hmac
  };
}

// 用法
const cred = generateTurnCredential('user123', 'YOUR_TURN_STATIC_AUTH_SECRET');
// → 传给前端 iceServers

5. 启动与验证

systemctl restart coturn
systemctl enable coturn
systemctl status coturn

# 查看监听端口
ss -lunp | grep turnserver

四、Docker 部署(开发/快速验证)

# docker-compose.yml
version: '3'
services:
  coturn:
    image: coturn/coturn:latest
    network_mode: host          # 必须 host 模式,否则 relay 端口映射复杂
    volumes:
      - ./turnserver.conf:/etc/turnserver.conf:ro
      - ./certs:/etc/coturn/certs:ro
    command: ["-c", "/etc/turnserver.conf"]
docker compose up -d

注意:network_mode: host 在 Linux 上有效;macOS/Windows Docker Desktop 不支持 host 网络,生产请直接装在 Linux 服务器上。

五、与 mediasoup / WebRTC 客户端的集成

1. 浏览器侧 iceServers 配置

const rtcConfig = {
  iceServers: [
    // 1. Google STUN(兜底,免费)
    { urls: 'stun:stun.l.google.com:19302' },

    // 2. 自建 STUN/TURN(同台 coturn 即可)
    {
      urls: [
        'stun:turn.yourdomain.com:3478',
        'turn:turn.yourdomain.com:3478?transport=udp',
        'turn:turn.yourdomain.com:3478?transport=tcp',
        'turns:turn.yourdomain.com:5349?transport=tcp'   // TURN-over-TLS
      ],
      username: cred.username,
      credential: cred.credential
    }
  ],
  iceTransportPolicy: 'all'   // 生产用 'all';仅 TURN 时用 'relay'
};

2. mediasoup 的特殊之处

mediasoup 服务器端不需要 STUN/TURN,详见 9.PeerJS 构建单对单视频通话.md（在新窗口打开）。

  • mediasoup 是 SFU,本身即中继,只需配置 announcedIp(公网 IP)
  • iceServers 仅配置在浏览器侧(WebRtcTransportOptions 不涉及此)
  • TURN 在 mediasoup 架构下基本用不上,但加一个 STUN 兜底是好习惯

3. PeerJS 客户端集成

const peer = new Peer(id, {
  host: 'signaling.yourdomain.com',
  path: '/myapp',
  config: {
    iceServers: [
      { urls: 'stun:stun.l.google.com:19302' },
      {
        urls: 'turn:turn.yourdomain.com:3478',
        username: cred.username,
        credential: cred.credential
      }
    ]
  }
});

六、托管式 TURN 服务(免运维方案)

适合不想自己搭服务器的项目:

服务商特点计费
Twilio NAT Traversal老牌,全球节点,SDK 易用按流量(GB)
Xirsys简单 API,小项目友好按流量/月费
Cloudflare Calls TURN新服务,全球 Anycast,低延迟按流量
Open Relay免费公共 TURN(仅测试用)免费,但限流

调用示例(Twilio):

// 后端调用 Twilio API 获取临时凭证
const token = await twilioClient.tokens.create();
// token.iceServers 直接返回配置好的 iceServers 数组

七、测试与验证

1. Trickle ICE 测试(官方工具)

打开 https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/ ,输入:

STUN/TURN URL: turn:turn.yourdomain.com:3478?transport=udp
Username: <生成的用户名>
Credential: <生成的密码>

预期看到候选者:

  • srflx —— STUN 工作正常
  • relay —— TURN 工作正常
  • host —— 本地候选者

# 测试 STUN

turnutils_uclient -u alice -w password -p 3478 turn.yourdomain.com

九、常见坑

问题原因解决
ICE 卡在 host,无 srflx防火墙阻断 UDP 出站开放 3478 UDP
relay 候选者不出现凭证错误或 realm 不匹配检查 lt-cred-mech 和生成凭证时的 realm
跨网段连不上external-ip 没配,relay 地址变成内网必须配 external-ip=公网IP
Docker 部署 relay 失败bridge 网络下 relay 端口无法映射改用 network_mode: host
偶发卡顿/丢包relay 端口范围太小或带宽不够扩大 min-port/max-port,升级带宽
TLS 端口连不上证书路径错误或权限不足检查 cert/pkey 路径与权限

十、总结

生产首选: coturn(自建)
├── 部署: Linux 公网服务器,Docker 或 apt
├── 配置: external-ip + realm + lt-cred-mech + TLS
├── 集成: 浏览器侧 iceServers(短期凭证动态下发)
├── mediasoup 场景: 仅浏览器侧加 STUN 兜底即可,基本用不到 TURN
└── 验证: Trickle ICE 工具 + DevTools 检查 srflx/relay 候选者

核心原则:

  • STUN 免费且简单,生产也照常用(配 Google 或自建均可)
  • TURN 必须自建或买托管,免费公共 TURN 不能上生产
  • mediasoup 架构下 TURN 的"中继"职责已被 SFU 取代,通常只需 STUN
