WebRTC 传输协议（RTP 与 SCTP）

概述

WebRTC 在 RTCPeerConnection 之上承载两类传输：

RTCPeerConnection
    ├── 音视频通道 → RTP/SRTP   （本文第一部分）
    └── 数据通道   → SCTP       （本文第二部分）

第一部分：RTP 实时传输协议

一、概述

RTP（实时传输协议）是 WebRTC 音视频数据传输的基础协议。

重要说明

WebRTC 实际使用的是 SRTP（安全 RTP），数据是加密的。

二、RTP 的特点

特点说明
低延迟专为实时场景设计
有序号和时间戳乱序到达时可以重组成正确顺序
基于 UDP性能好，但不保证可靠送达
支持多播未来可能支持多人通话

RTP 不提供什么

不提供说明
QoS 质量保证不保证延迟或带宽
资源预留不管理网络资源

QoS 监控由 RTCP 负责。

三、WebRTC 中的 RTP

每个 RTCPeerConnection 有三个 RTP 相关对象：

对象作用
RTCRtpSender编码并发送 MediaStreamTrack 数据
RTCRtpReceiver接收并解析远程轨道数据
RTCRtpTransceiverSender + Receiver 配对，共享同一媒体流

四、应用：实现"呼叫保持"

利用 RTP 接口，可以实现通话保持功能。

正常通话：A ←──── 双向交谈 ────→ B
          A: sendrecv          B: sendrecv

按下保持：A 按"保持"
          → A 这边：把麦克风换成音乐，同时不听 B 说话
          → B 那边：停止说话，只听 A 发来的音乐
          
          A(发音乐) ───── 单向音乐 ─────→ B(只听)
             sendonly                       recvonly

A保持（对方听音乐）

async function enableHold(audioStream) {
  // 1. 替换发送轨道为音乐
  await audioTransceiver.sender.replaceTrack(audioStream.getAudioTracks()[0]);
  
  // 2. 停止接收对方音频
  audioTransceiver.receiver.track.enabled = false;
  
  // 3. 切换为只发送模式
  audioTransceiver.direction = "sendonly";
}

B处理保持请求

async function holdRequested(offer) {
  await peerConnection.setRemoteDescription(offer);
  
  // 停止发送音频
  await audioTransceiver.sender.replaceTrack(null);
  
  // 切换为只接收模式
  audioTransceiver.direction = "recvonly";
  
  await sendAnswer();
}

A取消保持

async function disableHold(micStream) {
  // 恢复麦克风
  await audioTransceiver.sender.replaceTrack(micStream.getAudioTracks()[0]);
  
  // 恢复接收
  audioTransceiver.receiver.track.enabled = true;
  
  // 切换为双向模式
  audioTransceiver.direction = "sendrecv";
}

五、Transceiver 方向模式

模式说明
sendrecv双向传输
sendonly只发送
recvonly只接收
inactive不发不收

六、RTP 部分总结

WebRTC 音视频 = RTP/SRTP 传输层

- RTP 提供实时、低延迟的数据传输
- RTCP 负责 QoS 监控
- SRTP 加密保证安全
- RTCRtpSender/Receiver/Transceiver 管理媒体流

第二部分：WebRTC 数据通道（SCTP）（了解）

一、一句话理解

  • 实际没啥用

数据通道 = 浏览器之间的"直传通道"，不经过服务器，可发送任意数据（文本、二进制）。

二、核心特点

特点说明
点对点直连，不经过服务器
加密DTLS 自动加密
可配置可像 TCP（可靠） 或 UDP（不可靠）

三、两种创建方式

方式说明
自动协商（推荐）createDataChannel()，WebRTC 自动处理
手动协商negotiated: true，需自己告诉对方 ID

四、发送和接收

// 发送
channel.send("Hello!");
channel.send(arrayBuffer);

// 接收
channel.onmessage = (e) => console.log(e.data);

五、可靠 vs 不可靠

类型配置行为
可靠（像 TCP）ordered: true保序、保送达
不可靠（像 UDP）ordered: false, maxRetransmits: 0不保序、不重传

六、消息大小

  • 默认限制：64 KB
  • 通常支持：>= 256 KB
  • 可通过 SDP max-message-size 协商

七、完整示例

// 建立连接
const pc = new RTCPeerConnection();
const channel = pc.createDataChannel("chat");

// 打开通道
channel.onopen = () => channel.send("Hello!");

// 接收消息
channel.onmessage = (e) => console.log(e.data);

// 对方监听
pc.ondatachannel = (e) => {
  e.channel.onmessage = (ev) => console.log(ev.data);
};

八、注意事项

项目说明
需要信令服务器真实环境需交换 SDP/ICE
需要 STUN/TURN穿透 NAT
避免大消息会造成队头阻塞
