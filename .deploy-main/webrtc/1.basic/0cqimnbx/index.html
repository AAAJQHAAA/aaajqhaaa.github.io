媒体采集与约束完全指南

getUserMedia、MediaStream、MediaStreamTrack、MediaRecorder、Constrain* 约束模型

概述

媒体采集是 WebRTC 的第一步，负责从浏览器获取摄像头、麦克风、屏幕等媒体资源：

接口职责
MediaDevices媒体设备入口，枚举设备、请求权限
MediaStream媒体流，封装音视频轨打包传输
MediaStreamTrack媒体轨道，控制单路音视频
MediaRecorder媒体录制，本地保存为 WebM
Constrain*约束模型，精确控制设备参数

1. 媒体设备入口（MediaDevices）

🎯 学完能做：列设备清单、请求权限、理解安全上下文限制

全局入口：navigator.mediaDevices（只在安全上下文中存在）

MediaDevices（继承 EventTarget）
  ├─ enumerateDevices()                        → Promise<MediaDeviceInfo[]>
  │    列出所有音频入/出 + 视频输入设备；无权限时 deviceId/label 为空
  ├─ getUserMedia(constraints)                 → Promise<MediaStream>
  │    请求摄像头/麦克风权限并返回对应的音视频流
  ├─ getDisplayMedia(options?)                 → Promise<MediaStream>
  │    屏幕/窗口/标签页共享（每次调用都要用户选择，没有持久权限）
  └─ getSupportedConstraints()                 → MediaTrackSupportedConstraints
       返回浏览器支持的「约束能力」名表（{ echoCancellation: true, ... }）

MediaDeviceInfo（设备描述，只读）
  ├─ deviceId   DOMString      跨会话不稳定（除非持久化权限）
  ├─ groupId    DOMString      同一物理设备的 输入/输出 共享相同 groupId
  ├─ kind       "audioinput" | "audiooutput" | "videoinput"
  └─ label      DOMString      已获得权限时才返回人类可读名称
       ↓ 继承
InputDeviceInfo（仅 audioinput / videoinput）
  └─ getCapabilities() → MediaTrackCapabilities
       返回该输入设备的硬件能力范围（支持的分辨率、帧率、回声消除是否支持等）

2. 约束模型（Constrain*）

🎯 学完能做：精确控制设备参数，当设备不满足时给出正确的降级 UI

getUserMedia(constraints) 和 track.applyConstraints() 共用同一套约束模型。

五种基础约束类型

约束类型TS 类型写法典型属性
ConstrainBooleanboolean | ConstrainBooleanParameters{ exact?: boolean; ideal?: boolean }
ConstrainBooleanOrDOMStringboolean | string | ConstrainBooleanOrDOMStringParameters用于 echoCancellation 等历史上类型摇摆的属性
ConstrainDOMStringstring | string[] | ConstrainDOMStringParameters如 deviceId、facingMode
ConstrainDoublenumber | ConstrainDoubleRange在 DoubleRange{min,max} 基础上多 exact/ideal；如 frameRate、aspectRatio
ConstrainULongnumber | ConstrainULongRange在 ULongRange{min,max} 基础上多 exact/ideal；如 width、height、channelCount

约束优先级（从高到低）

  1. exact：必须满足；设备做不到 → 抛 OverconstrainedError
  2. min / max：硬性范围；超出范围就不满足
  3. ideal：理想值；尽量匹配，不匹配也不报错
  4. advanced: MediaTrackConstraintSet[]：高级回退数组；按顺序尝试，至少满足一套

MediaTrackConstraints（常用属性一览）

video: {
  width: { ideal: 1920 }, height: { ideal: 1080 },
  frameRate: { min: 24, ideal: 30 },
  aspectRatio: { ideal: 16 / 9 },
  facingMode: { ideal: "environment" },   // "user" | "environment" | "left" | "right"
  deviceId: { exact: persistentIdGotFromEnumerateDevices },
  resizeMode: "none" | "crop-and-scale",
  displaySurface: "monitor" | "window" | "browser",   // getDisplayMedia 专用
  backgroundBlur: "include-if-supported",             // 新版浏览器背景虚化
}
audio: {
  echoCancellation: true,
  noiseSuppression: { ideal: true },
  autoGainControl: true,
  channelCount: 1,
  sampleRate: 48000,
  sampleSize: 16,
  latency: { ideal: 0.02 },  // 20ms 目标
  deviceId: "...",
}

3. 约束错误（OverconstrainedError）

🎯 学完能做：正确区分权限拒绝和约束不满足，给出正确的降级 UI

OverconstrainedError（继承 DOMException）
  ├─ .name === "OverconstrainedError"
  ├─ .message 人类可读说明
  └─ .constraint  触发冲突的那个属性名（如 "width"），非常有用！

典型应对：

try { await track.applyConstraints(tooStrict); }
catch (err) {
  if (err.name === 'OverconstrainedError') {
    console.warn(`设备无法满足约束「${err.constraint}」，自动降级`);
    await track.applyConstraints({ [err.constraint]: undefined }); // 放弃该约束
  }
}

4. 媒体流（MediaStream）

🎯 学完能做：把多路音视频轨打包成流，在会话中动态增删轨道

MediaStream（继承 EventTarget）
  ├─ 构造：new MediaStream(); new MediaStream(tracks); new MediaStream(otherStream)
  ├─ 属性：
  │   ├─ id        DOMString  (UUIDv4 级别唯一，同源刷新就变)
  │   └─ active    boolean    (至少一条 "live" 轨才为 true)
  ├─ 事件：
  │   ├─ addtrack     (Event: MediaStreamTrackEvent)  一条轨被加入
  │   └─ removetrack  (Event: MediaStreamTrackEvent)  一条轨被移除
  └─ 方法：
      ├─ addTrack(track) / removeTrack(track)
      ├─ getTracks()         → MediaStreamTrack[]   (音频+视频)
      ├─ getAudioTracks()    → MediaStreamTrack[]
      ├─ getVideoTracks()    → MediaStreamTrack[]
      ├─ getTrackById(id)    → MediaStreamTrack | null
      └─ clone()             → MediaStream   (深度克隆所有 track 的克隆)

典型用法：

video.srcObject = stream;        // <video> 直接绑定 MediaStream 播放

5. 媒体轨道（MediaStreamTrack + WebAudio 桥接）

🎯 学完能做：静音/开关摄像头、切换前后摄像头、查询设备能力、WebAudio 实时处理

MediaStreamTrack（继承 EventTarget）
  ├─ 只读属性：
  │   ├─ id / kind("audio" | "video") / label
  │   ├─ muted        boolean  (临时没有数据输入，不一定是人为操作)
  │   ├─ readyState   "live" | "ended"   (stop() 后变 ended)
  │   └─ contentHint  "" | "speech" | "music" | "motion" | "detail" | "text"
  │        给编码器的"这路内容更像什么"提示（更省码率/更清晰）
  ├─ 可写属性：
  │   └─ enabled      boolean  (true=发真实数据; false=发静音/黑帧。本地预览仍可见)
  ├─ 事件：ended / mute / unmute
  └─ 方法：
      ├─ applyConstraints(constraints?)              → Promise<void>
      ├─ getCapabilities()         → MediaTrackCapabilities   (设备硬件能做到什么)
      ├─ getConstraints()          → MediaTrackConstraints    (当前请求的约束)
      ├─ getSettings()             → MediaTrackSettings       (当前实际生效的参数)
      ├─ clone()                   → MediaStreamTrack         (独立副本)
      └─ stop()                    → void                     (永久关闭；释放摄像头灯)

MediaStreamTrackEvent（addtrack/removetrack 专用事件）
  └─ .track : MediaStreamTrack

WebAudio 桥接节点（MediaCapture 规范附带）：

AudioContext
  ├─ createMediaStreamSource(stream)      → MediaStreamAudioSourceNode
  │    把一条 MediaStream 的音频输入接入 WebAudio 管线（做 EQ / 可视化 / VAD）
  └─ createMediaStreamDestination()       → MediaStreamAudioDestinationNode
       把 WebAudio 输出变成一条 MediaStream，可送进 RTCPeerConnection.addTrack()
       └─ .stream : MediaStream  (只含 1 条音频轨)

6. 媒体录制（MediaRecorder + BlobEvent）

🎯 学完能做：把 MediaStream 录成 WebM Blob、分段上传、下载到本地。完全不涉及网络传输

MediaRecorder（继承 EventTarget）
  ├─ 构造：new MediaRecorder(stream, {
  │           mimeType?; audioBitsPerSecond?; videoBitsPerSecond?; bitsPerSecond? })
  ├─ 静态：isTypeSupported("video/webm;codecs=vp9,opus") → boolean
  ├─ 属性：
  │   ├─ state  "inactive" | "recording" | "paused"
  │   ├─ stream / mimeType / videoBitsPerSecond / audioBitsPerSecond
  │   └─ videoBitsPerSecond 注意：一旦 start() 就不可改
  ├─ 事件：start / pause / resume / stop /
  │         dataavailable(BlobEvent) / error(MediaRecorderErrorEvent)
  └─ 方法：start(timeslice?)     // timeslice(ms) 每隔 N 毫秒抛一次 dataavailable
          stop() / pause() / resume() / requestData()

BlobEvent（继承 Event）
  └─ .data : Blob    // 录制好的这一段二进制（通常是 WebM 分片）

典型用法：

const recorder = new MediaRecorder(stream, { mimeType: 'video/webm;codecs=vp9,opus' });
const chunks = [];

recorder.ondataavailable = (e) => chunks.push(e.data);
recorder.onstop = () => {
  const blob = new Blob(chunks, { type: 'video/webm' });
  // 上传或下载
};

recorder.start(1000);  // 每 1 秒抛一次 dataavailable
